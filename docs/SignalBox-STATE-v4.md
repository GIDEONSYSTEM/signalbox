## 0. Что это и куда движется

Утилита для студий подкастов: мониторинг и управление камерами Sony по Wi-Fi
(Sony Camera Remote SDK, PC Remote / PTP-IP). Один C++ процесс без окна: находит камеры,
опрашивает ~1/сек, поднимает HTTP-сервер на **:8787** и отдаёт панель управления.
Панель открывают в браузере, на телефоне или цепляют в OBS как Custom Browser Dock.

**Планы владельца (важно для решений):**
- 💰 **программу будут продавать** — сейчас идёт бесплатное тестирование с несколькими студиями;
- 🔒 позже — лицензирование (см. §9);
- 🍎 позже — версия под **Mac Apple Silicon** (см. §9).

**Камеры, виденные в работе:** ZV-E1 (192.168.0.83, .129), ILME-FX30 (192.168.0.238).
Заявлялись также ZV-E10 II (`ZV-E10M2`) и FX3.

## 2. HTTP API (порт 8787, `INADDR_ANY`)

- `GET /status.json` → `{server, cameras:[{id,model,ip,online,rec,battery,acPower,cardMinutes,
  writing,iso,isoEff,aperture{cur,opts},shutter{cur,opts},wb{cur,opts},wbKelvin,micGain{cur,opts}}]}`
- `POST /cmd` → `{cam:N|"all", action, value}` **или** `{cams:["ip",…], action, value}` (группа одним
  запросом). `action`: `rec|iso|aperture|shutter|wb|wbkelvin|micgain`
- `GET /cameras.json` · `POST /cameras/add {ip,model,ssh}` · `POST /cameras/remove {ip}`
- `GET /groups.json` · `POST /groups/save` (схемой владеет панель, C++ только персистит)
- `GET /update.json` · `POST /update/check` · `POST /update/install` · `POST /update/settings {auto}`
- `POST /restart` · `POST /shutdown`
- `GET /liveview/<n>.jpg?seq=N` → JPEG + заголовки `X-Cam-Frames`, `X-Cam-Seq`; **304** если кадр не менялся
- `GET /` панель · `GET /<file>` статика из `www\`

**Выбор LAN-адреса для `server`:** `GetAdaptersAddresses`; пропуск выключенных и loopback;
вес = `ipScore` −60 за виртуальный IfType (tunnel 131 / PPP 23 / propVirtual 53) +25 за настоящий
шлюз. Кандидаты и веса — в лог строками `[net]`.
⚠️ **Не определять адрес «маршрутом в интернет»** (UDP connect к 8.8.8.8): при VPN проба уходит
в туннель — проверено, выбирался `172.18.0.1` (xray_tun) вместо `192.168.0.176`.

## 3. Устройство процесса

**Без консоли.** `WIN32_EXECUTABLE TRUE` + `/ENTRY:mainCRTStartup` (Windows GUI, но обычный
`main()`). При старте сам открывает панель в браузере; при само-перезапуске получает `--restarted`
и вкладку не открывает. Весь `consolePrintf` → **`SignalBox.log`** рядом с exe (прошлый запуск →
`.log.prev`), открыт `_wfsopen(_SH_DENYNO)` + UTF-8 BOM.
⚠️ `[System.IO.File]::ReadAllText` лог на живой программе НЕ прочитает — читать `Get-Content`
или явным `FileShare.ReadWrite`.

**Значок в трее и главный поток.** `plat::runEventLoop()` (в слое): message-only окно
(`SignalBoxTrayWnd`, родитель `HWND_MESSAGE`) + `Shell_NotifyIconW`, меню — открыть панель /
перезапустить / выключить. Цикл просыпается раз в 150 мс и смотрит `g_running`.
🔴 **Цикл событий крутится на ГЛАВНОМ потоке, HTTP-сервер — в рабочем** (до 2026-08-10 было
наоборот). Причина: на macOS status bar item поднимается только с главного потока, иначе порт
пришлось бы выворачивать наизнанку.
⚠️ **Проверять значок через `FindWindow*` нельзя** — message-only окна так не находятся
(дважды получал ложное «нет»). Достоверно — строки лога `[tray] …`; пункты меню тестировать
посылкой `WM_COMMAND` с id в hwnd из лога.

**Единственный экземпляр.** Мьютекс `Local\SignalBox_SingleInstance`. Второй запуск открывает
панель работающего и выходит. Проверка стоит **до `openLogFile()`** (иначе второй экземпляр
затрёт лог живого); при `--restarted` ждёт до ~15с, а `relaunchSelf()` перед `CreateProcessW`
зовёт `releaseSingleInstance()` — без этого ломалась кнопка «Перезапустить».

**Сторож завершения.** `startShutdownWatchdog(8)` → через 8с `TerminateProcess`. Нужен потому,
что `poller.join()`/`discoverer.join()` могут висеть внутри блокирующего SDK `Connect()` к
несвязанной камере — так появлялись **зомби-процессы** (порт освобождён, процесс жив).
🔴 **Порядок в конце `main()` важен:** сначала дождаться потока сервера и закрыть сокет, и только
ПОТОМ заводить сторожа. Браузер держит открытые соединения, приём последнего запроса занимает
до 4с (`SO_RCVTIMEO`); пока это ожидание было внутри восьмисекундного окна, штатное выключение
не укладывалось и процесс каждый раз добивался принудительно (замерено: 8.2с и «затянулось»
против 1.0с и «Готово.»).

**Брандмауэр.** `maybeOfferFirewallRules()` через COM `INetFwPolicy2` ищет входящее Allow-правило
на свой exe; нет — MessageBox, при согласии `ShellExecuteExW("runas", "--firewall")` → UAC →
элевированный экземпляр добавляет TCP+UDP с `NET_FW_PROFILE2_ALL`. Отказ → `firewall-skip.txt`.
Ветка `--firewall` обрабатывается **до** single-instance-гарда.

**Свойства камер:** статус `GetSelectDeviceProperties` ~1/сек; rec = `SendCommand(MovieRecord,
Down→Up)`; iso маска `& 0x00FFFFFF`, AUTO=`0xFFFFFF`; **кельвины — только `Colortemp`=0x0115**
(UInt16), НЕ `WhiteBalancePresetColorTemperature`(0x2A5); **микрофон — `AudioInputMasterLevel`**
(UInt16Range, у ZV-E1 диапазон 0..31 шаг 1, проверено на живой камере).

**MIDI (winmm):** триггер **CC канал 1 (0xB0), контроллер #17**, дебаунс 80мс → тумблер записи на всех.

⚠️ **ГРАБЛЯ:** `snprintf("%.4f")` на RU-локали печатает **запятую** → битый JSON. Числа
форматировать локале-независимо (`fx4()`).

## 4. Обнаружение камер — три пути

1. **Автопоиск** `EnumCameraObjects` (SSDP-мультикаст). Параметр `timeInSec` Sony документирует
   как **неподдерживаемый** — окно сканирования не увеличить.
2. **Ручные камеры — `cameras.txt`** (`IP МОДЕЛЬ [ssh]`), управляется из панели
   (Настройки → Камеры): `CreateCameraObjectInfoEthernetConnection` без перечисления.
3. **Автозапомненные — `cameras-known.txt`** (ведёт программа сама, `MAC IP МОДЕЛЬ`). Каждая
   найденная автопоиском камера туда пишется; если позже автопоиск её не увидит — подключаемся
   по сохранённому адресу. Смена IP по DHCP → поиск по MAC в `GetIpNetTable2`. Строгая ARP-проверка
   живости, иначе тихо пропускаем.

**Байт-порядок IP для SDK:** 1-й октет → биты 7..0 … 4-й → 31..24, т.е. `192.168.0.5 = 0x0500A8C0`
— ровно то, что даёт `inet_pton` в `S_un.S_addr`. Не менять на htonl.
**MAC не обязан быть настоящим** — по доке это лишь идентификатор объекта.

### 🔴 Почему камеры не находятся в чужой студии — РЕАЛЬНАЯ ПРИЧИНА

Находка коллеги: на роутере в **2.4 ГГц стояла ширина канала 20/40 МГц** — камера не находилась;
переключили на **20 МГц** — заработало. В студии владельца тоже 20/40, но там всё работает,
потому что помещение маленькое и эфир чистый.

Механизм: в 2.4 ГГц всего 3 непересекающихся канала, HT40 занимает полдиапазона; мощность
размазывается на вдвое широкую полосу (−3 дБ SNR), плюс при соседних сетях точка постоянно
дёргается 20↔40. Мультикаст не подтверждается и не переотправляется → отваливается первым,
unicast выживает за счёт ретраев. Отсюда «ping идёт, а камеры нет».

**Рекомендация (в `ЧИТАЙ-МЕНЯ.txt`):** 2.4 ГГц → строго **20 МГц**, канал вручную 1/6/11.
Прочие подозреваемые: фильтрация мультикаста на точке, IGMP snooping без querier, Wi-Fi в другой
подсети/VLAN, репитер.
⚠️ Моя гипотеза про профиль брандмауэра для ЭТОГО случая **не подтвердилась** — причина
оказалась радиочастотной. Спрашивать про ширину канала раньше, чем про брандмауэр.

## 6. Панель

`LV_BASE` = origin страницы (или `127.0.0.1:8787` для `file://`) → работает и с телефона.
**Порядок блоков:** шапка → «+ Группа» → группы → камеры без группы.
Всё конфигурационное переехало в окно настроек.

**Шапка:** слева логотип и **шестерёнка** (настройки); справа — метка «↑ версия» (если есть
обновление), квадратные кнопки-иконки перезагрузки и выключения, бейдж live.

**Окно настроек** (`#settings`): поверх панели, слева список разделов, справа содержимое —
как в OBS. Разделы: **Камеры** (добавление по IP), **Доступ** (адрес + QR), **Обновление**.
Закрывается крестиком, кликом по фону и Escape. Блоки туда **перенесены, не скопированы** —
иначе разъехались бы две версии одних настроек.

**Группы (съёмочные залы):** плиткой по ширине (`#groupsWrap` grid, `auto-fit`, колонка
ровно **392px** — с `1fr` растягивались в две карточки), внутри группы камеры **вертикально**,
всё центрировано. В шапке группы: треугольник сворачивания, имя (правится на месте),
**индикатор REC** (горит, только если пишут ВСЕ камеры; пустая группа не считается),
«Запись»/«Стоп», счётчик, ✕. Ниже ряд регуляторов ISO / Диафр. / Выдержка / ББ (±).
- **Свёрнутое состояние — в `localStorage`, НЕ на сервере**: каждый оператор сворачивает чужие
  залы у себя на телефоне, не влияя на док OBS и соседей.
- Перетаскивание карточек между группами (HTML5 DnD) + `<select>` «Группа» в карточке для тача.
- **Групповая запись — ОДИН запрос** `{cams:[…]}`, чтобы старт пришёлся на один проход; шаги
  ISO/диафрагмы/выдержки/ББ считаются **для каждой камеры от её значения** и уходят отдельными
  `/cmd` (не дублируем таблицы значений в C++).

**Карточка:** модель, батарея, молния питания, остаток карты, STBY/REC; строка «Группа»;
ряд **[Запись 84px] [ISO по содержимому] [Mic Gain]** высотой 31px; ниже диафрагма/выдержка/ББ;
Live Preview с рамками и поворотом. **Mic Gain скрывается**, если камера уровень не отдаёт.

**Модель камеры:** таблица `MODEL_NAMES` с **точным** совпадением + фолбэк «как есть, без
префикса ILME/ILCE/DSC/PXW/HXR». ⚠️ Раньше был поиск подстроки — `ILME-FX30` попадал под правило
`FX3`, и FX30 показывалась как FX3.

**Live Preview:** искусственный потолок 7 к/с снят — частоту задаёт камера.
**Замер на живой ZV-E1: ~20 к/с**, кадр 12–42 КБ, 2–5 Мбит/с на превью. Чтобы однопоточный
сервер не захлебнулся, у кадров есть `seq`: клиент шлёт свой, сервер отвечает **304** без тела,
если кадр не менялся. Клиент опрашивает каждые 33 мс.
🐞 **До 2026-08-11 ветка 304 не срабатывала НИКОГДА:** сервер искал `seq=` в `req.path`, а строку
запроса `HttpServer` отрезает в `req.query` ещё при разборе — значит `haveSeq` всегда оставался
−1 и каждый кадр уходил целиком, даже неизменившийся. Панель при этом всё делала правильно
(`if(r.status === 304) return;`). После починки замерено: 60 запросов подряд каждые 20 мс →
**21 ответ 304 без тела**, 39 с кадром.
⚠️ **Как это проверять:** редкими запросами (раз в секунду) баг не виден — на живой камере кадр
успевает смениться, и 200 в ответ совершенно правилен. Нужны частые запросы и подсчёт кодов.
⚠️ **Браузер тормозит таймеры в фоновой вкладке** — в свёрнутом доке частота падает; это
поведение браузера, не наше. Мерить частоту только при видимой вкладке, иначе получишь чушь
(я получал «1 к/с» и «453 к/с»).

**QR:** библиотека **qrcode-generator** (MIT, `www/qrcode.js`), локально. Клик → крупный оверлей.
**Шрифты локальные** — внешний `<link>` на Google Fonts блокировал отрисовку (на телефоне с VPN
страница висела чёрной до тайм-аута).

## 7. Обновления через GitHub Releases

Репозиторий **`GIDEONSYSTEM/signalbox`** (публичный — только на время тестирования, см. §9).
Версия — `kAppVersion` в `main.cpp`; репозиторий — `kUpdateRepo` (пустая строка = проверка выключена).

**Как работает:** проверка при запуске и **раз в 4 часа** через **WinHTTP** (встроен в Windows):
`api.github.com/repos/<repo>/releases/latest` → `tag_name` + первый `.zip`-ассет → `cmpVersion`
почастно (чтобы 1.10 > 1.9). Панель показывает метку «↑ версия» в шапке и плашку в настройках.

**Установка без отдельного инсталлятора:** занятый exe и загруженные DLL не перезаписать, поэтому
архив качается в `%TEMP%\SignalBox-update\`, распаковывается встроенным **`tar.exe`**, затем
запускается распакованная копия с `--apply-update "<target>" <pid>` — она ждёт выхода старого
процесса, копирует **`robocopy`** (успех = код < 8) и стартует обновлённую программу.
Ветка `--apply-update` — **до** single-instance-гарда.

**Автообновление** — `settings.json` + галка «авто» в настройках, по умолчанию ВЫКЛ
(решение владельца: уведомление + кнопка, но с возможностью включить авто).

### Правила выпуска версии
1. поднять `kAppVersion` в `main.cpp` — это **единственное место**, где живёт версия;
2. собрать на каждой ОС и упаковать своим скриптом:
   - Windows: `powershell -ExecutionPolicy Bypass -File tools\pack-win.ps1`
   - macOS: `bash tools/pack-mac.sh`
   оба читают версию из `main.cpp`, кладут результат в `dist/` и **сами проверяют архив

⚠️ **Тег обязан быть номером версии.** Первый релиз вышел с тегом `Minor` — `cmpVersion` счёл

## 9. Коммерческий контекст и планы (важно для решений)

если брать их, обновления логичнее прицепить туда же.

## 10. 🔴 Уроки методологии (читать до начала работы)

1. **Свой энкодер нельзя валидировать своим декодером.** С QR я дважды отчитался об успехе на
   сломанном коде: round-trip сходился и RS-синдромы были нулевыми **потому что я считывал ровно
   то, что сам записал, в том же (неверном) порядке**. Нужен независимый декодер или живой сканер.
   Итог: самописный генератор выброшен, взята библиотека — подтверждено сканом с телефона.
2. **Не тестировать на живых данных юзера.** Дважды затирал его группы. Правильно: снять копию
   `groups.json` до теста и вернуть после; ещё лучше — проверять вычисленными стилями/DOM или
   подменять только ответ сервера в браузере, не мутируя данные.
3. **Синхронизировать три копии сразу** (§1) и напоминать про Ctrl+F5.
4. **Проверять фактами, а не рассуждением.** Гипотеза «профиль брандмауэра» звучала стройно,
   а реальной причиной оказалась ширина канала Wi-Fi. Возможности камеры выяснять дампом
   свойств с живой камеры, а не догадками по документации.
5. **Замеры делать в честных условиях.** Браузер в фоне режет таймеры; окно активности превью
   закрывается через 1.5с — из-за этого получал бессмысленные цифры, пока не померил со стороны
   сервера при открытом превью.

## 11. Грабли (must-know)

- Выключать только кнопкой на панели или из трея. Убийство процесса → камера отклоняет новое
  подключение (`0x820A`). Имя ПК для связывания: `WIN-T1I0U6MAIDA`.
- **`Настр. аутент. доступа` (SSH) на камере отключает «Связывание»** — при включённой
  аутентификации наш путь подключения не работает. Проверять первым делом.
- RU-локаль + `snprintf("%f")` → запятая → битый JSON.
- Рамки фокуса требуют `OSDImageMode=On` (HDMI при этом чистый).
- CAM-нумерация — по порядку обнаружения, между запусками перетасовывается. **Ключ камеры для
  групп — IP.** В `updateCard` обязателен `if(d.ip) e.ip = d.ip;` — иначе карточка сохранит IP
  прошлой камеры и уедет в чужую группу.
- POST_BUILD `copy_directory` может разово упасть сразу после линковки (антивирус держит свежий
  exe) — просто повторить сборку.
- `CrDevicePropertyCode` — **перечисление, а не namespace**: писать
  `SDK::CrDevicePropertyCode::CrDeviceProperty_X`, алиас `namespace P = …` не компилируется.
- Кнопки REC боевые: пишут на карты камер.

### Починено по итогам прогона (2026-08-11)

- 🐞 **`SignalBox.exe` было зашито в установщик обновления** (три места в `main.cpp`): проверка

  приложение»), на macOS теперь подсказка про Локальную сеть. `#ifdef` в прикладной код не
  добавлялся — граница слоя цела.
- 🎨 **В строке меню вместо логотипа Wi-Fi висел знак `◉`** (заглушка «до появления своей иконки»).
  Теперь системный символ **`wifi`** — тот же рисунок, что в `res/icon.ico` на Windows. Взят
  именно символ, а не сама `icon.ico`: в строке меню полагается монохромная **template**-картинка,
  которая сама подстраивается под светлую/тёмную тему и высоту строки, а цветная иконка выглядит
  чужеродно и мылится. ⚠️ `setTemplate:` вызывать **сообщением**, не через точку: свойство
  называется `template`, а это ключевое слово C++, и файл собирается как ObjC++.

- состав задан **списком разрешённого, а не исключений** — первый релиз проекта уехал с
  `cameras.txt` внутри (§7), и при обратной логике достаточно забыть один файл;
- внутри обязательна папка `SignalBox/` — установщик ищет `<распаковано>/SignalBox/SignalBox`;
- панель берётся из `build/Release/www` (источник правды), а не из копии в `build-mac/www`;
- адаптеры кладутся в `Contents/Frameworks/CrAdapter`;
- снимается карантин: `xattr -c` через `find`, потому что **у `xattr` на macOS 15 нет `-r`**;
- в конце **самопроверка**: архив распаковывается тем же `ditto`, что и у установщика, и
  проверяется раскладка — нет `SignalBox/SignalBox` или затесались данные установки, скрипт падает.
- ℹ️ Файлы `._имя` внутри архива — норма: `com.apple.provenance` пользователю не снять, и `ditto`
  хранит его рядом с файлом. При распаковке `ditto` и Архиватором macOS они склеиваются обратно
  (проверено: в распакованном дереве их ноль). Карантин при этом снят, а мешает запуску только он.

### .app-бандл (2026-08-11)

✅ **Программа под macOS собирается настоящим `SignalBox.app`, а не голым бинарником.** Проверено
на живой машине: запуск через `open`, камера подключается, панель отдаётся, перезапуск и
выключение работают, значок в строке меню на месте.

**Зачем это было нужно** (по убыванию важности):
- 🔴 **Разрешение «Локальная сеть» теперь выдаётся SignalBox, а не Терминалу.** Замерено прямо:
  до выдачи разрешения автопоиск камеру не видел (`Автопоиск не увидел ZV-E1 — подключаюсь по
  сохранённому адресу`), после — `Обнаружена камера: ZV-E1`. У голого бинарника разрешение
  получал запускающий Терминал, и на чужой машине это был бы вечный источник «камеры не находятся».
- двойной клик раньше открывал Терминал, теперь запускает программу;
- подписать и нотаризовать можно только бандл;
- появилась иконка (`res/icon.icns`, собирается из `res/icon.ico` через `tools/make-icns.sh`).

**Раскладка** (её же ждёт установщик обновления):
```
SignalBox.app/Contents/
  MacOS/SignalBox            Info.plist
  Frameworks/*.dylib         Frameworks/CrAdapter/   ← адаптеры SDK
  Resources/www/             Resources/icon.icns
```
Адаптеры лежат внутри бандла не случайно: `libCr_Core` ищет их по
`[[NSBundle mainBundle] bundlePath]` + `Contents/Frameworks/CrAdapter` (проверено `nm`/`strings`
по самой библиотеке). У голого бинарника `bundlePath` — это папка с ним, поэтому сэмпл Sony и
клал `Contents/Frameworks` рядом с exe; в настоящем бандле путь сходится сам собой.

🔴 **Данные переехали в `~/Library/Application Support/SignalBox/`** (`plat::dataDir()`): туда
теперь пишутся `cameras.txt`, `cameras-known.txt`, `groups.json`, `settings.json` и **лог**.
Внутрь бандла писать нельзя — **любая запись ломает подпись приложения**, а без валидной подписи
нотаризация бессмысленна; вдобавок обновление заменяет бандл целиком и унесло бы данные студии.
Проверено: после полного цикла работы `codesign --verify --strict` проходит, внутри бандла не
появилось ни одного файла данных.
⚠️ **При переходе на бандл данные надо перенести руками** — программа старое место не ищет.
На этой машине перенесены `cameras.txt`, `cameras-known.txt`, `groups.json` (в нём была живая
группа GREEN).
**На Windows ничего не изменилось:** `dataDir()`/`resourceDir()`/`installRoot()` там все три
возвращают `exeDir()`, раскладка «данные рядом с exe» (§5) прежняя.

**Обновление теперь заменяет бандл целиком.** Внутри архива лежит `SignalBox.app` (на Windows —
папка `SignalBox`, `payloadName()` в `main.cpp`), цель — `plat::installRoot()`, а путь к бинарнику
внутри копии считается от собственных путей (`Contents/MacOS/SignalBox` против `SignalBox.exe`),
чтобы раскладка не жила в коде второй константой.

**Подпись.** CMake подписывает бандл в POST_BUILD **после** укладки содержимого — иначе
`codesign --verify` говорит «code has no resources but signature indicates they must be present»,
и это блокер для нотаризации. По умолчанию подпись ad-hoc; для релиза передать сертификат:
```
cmake -S . -B build-mac -DCMAKE_BUILD_TYPE=Release \
      -DSIGNALBOX_CODESIGN_IDENTITY="Developer ID Application: ИМЯ (TEAMID)"
```
💰 **Нотаризация всё ещё не сделана — нужен сертификат владельца** (99 $/год). Библиотеки Sony
идут от самой Sony только с ad-hoc подписью (проверено `codesign`), поэтому на чужом Mac
Gatekeeper будет ругаться на каждую. Порядок для релиза расписан в шапке `tools/pack-mac.sh`:
пересобрать с сертификатом → упаковать → `xcrun notarytool submit --wait` → `stapler staple` →
упаковать заново.
⚠️ **Наблюдение про ad-hoc:** распакованная в другое место копия просила разрешение «Локальная
сеть» заново (автопоиск снова не видел камеру, спасал сохранённый адрес). Похоже, без стабильной
подписи macOS считает копию по новому пути другим приложением. С Developer ID личность приложения
постоянна — ещё один довод за сертификат, помимо Gatekeeper.

⚠️ **Первый запуск сразу после пересборки тянется десятки секунд** (замерял 30 с и больше 90 с):
система заново проверяет свежесозданный бинарник и неподписанные dylib Sony. Дальше запуски
обычные — перезапуск с уже проверенным бинарником поднимает сервер за ~5 с. Не считать это
зависанием: процесс жив, просто молчит; смотреть `SignalBox.log`, а не «отвечает ли порт».
⚠️ И не читать лог сразу после старта: новый экземпляр переименовывает `SignalBox.log` в `.prev`
и заводит пустой, так что в первые секунды `grep` попадает ещё в **старый** файл и показывает
прошлый запуск. Обжигался на этом дважды — ждать появления строки `[tray]`.
⚠️ **Перед пересборкой SignalBox надо выключить** — ровно как на Windows: работающий бинарник
macOS перезаписать не даст (`ETXTBSY`).
⚠️ **Панель на Mac правится в `build/Release/www`, а НЕ в `build-mac/www`**: CMake копирует туда
первую поверх второй при каждой сборке (`CMakeLists.txt:151`), и правка в `build-mac/www` тихо
пропадёт — это тот же капкан «трёх копий» из §1, только в другой обёртке. Вся папка `build-mac/`
генерируемая и добавлена в `.gitignore`.

Что выяснено фактами:
- 🔴 **Gatekeeper блокирует dylib Sony**, они не подписаны и не нотаризованы. `xattr -dr
  com.apple.quarantine` на пакет SDK **НЕ помог** (проверено) — пришлось прожимать каждую
  библиотеку вручную через Системные настройки → Конфиденциальность и безопасность → «Всё равно
  разрешить». 💰 Для продаж это значит подпись Apple Developer + нотаризацию всей сборки вместе
  с библиотеками Sony (99 $/год); на Windows аналога нет.
- 🔴 **`CrChar` зависит от `UNICODE`** (`CrTypes.h`): с ним `wchar_t`, без него `char`. Сэмпл Sony
  определяет `UNICODE` **только под Windows** (`RemoteCli/CMakeLists.txt:76`), значит на macOS SDK
  отдаёт обычный UTF-8 `char*`. У нас это разруливает перегрузка `plat::utf8From`, а `UNICODE` в
  CMake теперь под `if(WIN32)` — определить его на Mac значит разойтись с dylib по ABI.
- ✅ `libCr_Core.dylib` из пакета `CrSDK_v2.02.00_20260610a_Mac` — **universal (x86_64 + arm64)**,
  проверено `lipo` на M1. Порт нативный, Rosetta не нужен.
- 🔴 **Адаптеры на macOS ищутся в `Contents/Frameworks/CrAdapter`**, а не рядом с бинарником, как
  на Windows (так делает сэмпл Sony). CMake переносит их туда сам.
- ⚠️ macOS 14+ требует разрешение **Local Network**, иначе автопоиск (SSDP-мультикаст) молча
  ничего не находит. Для запуска из Terminal разрешение выдаётся Терминалу:
  Системные настройки → Конфиденциальность → Локальная сеть.
- Брандмауэр: `firewallSupported()` = false — понятия «правило на приложение заранее» в macOS нет,
  система спрашивает сама при первом входящем соединении.

**Правила слоя:** в `Platform.h` нет системных заголовков; все строки и пути — **UTF-8
`std::string`** (конверсия в `wchar_t` спрятана внутри реализации); функции не бросают исключений.
Заодно ушёл `std::ifstream(std::wstring)` — это расширение MSVC, которого нет нигде больше.

**Что обязана дать реализация под новую ОС:**

| Группа | Функции | Замечания для macOS |

Где бандлов нет — все три равны `exeDir()` |
| Архив | `extractArchive`, `copyTree` | на Windows — `tar.exe` и `robocopy /E` (без `/PURGE`: данные студии не стирать) |

**`HttpServer.h`** намеренно НЕ в слое: сокеты BSD одинаковы везде, различий на десяток строк, и
они собраны в шим в начале файла (`Socket`, `closeSocket`, `sendAll`, `recvSome`,
`setRecvTimeout`, `setNoSigPipe`). ⚠️ Ветка POSIX **написана, но ни разу не компилировалась**.
`setNoSigPipe` там не для красоты: без `SO_NOSIGPIPE` запись в закрытое клиентом соединение
убивает весь процесс сигналом.

**Байт-порядок IP** (`ipv4ToNumber`) — как раньше: 1-й октет в младший байт, `0x0500A8C0` для
192.168.0.5. Это то, что даёт `inet_pton` на little-endian, а и Windows x64, и Apple Silicon
такие. `htonl` не нужен.
