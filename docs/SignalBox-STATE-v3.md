## 0. Что это

Студия подкастов. Утилита **SignalBox** (Фаза 2; до 2026-08-04 называлась `CamCollector`) —
мониторинг и управление камерами Sony по Wi-Fi (Sony Camera Remote SDK, PC Remote / PTP-IP).

Один C++ процесс: подключается ко всем камерам, опрашивает ~1/сек, поднимает HTTP-сервер
на **:8787**, отдаёт панель (HTML) и live view. OBS цепляет панель как **Custom Browser Dock**,
телефоны заходят по LAN-адресу.

**Камеры, реально виденные в работе:** ZV-E1 (192.168.0.83, 192.168.0.129), **ILME-FX30**
(192.168.0.238). Также заявлялись ZV-E10 II (`ZV-E10M2`) и FX3.

## 2. HTTP API (порт 8787, `INADDR_ANY`)

- `GET /status.json` → `{server, cameras:[{id,model,ip,online,rec,battery,acPower,cardMinutes,
  writing,iso,isoEff,aperture{cur,opts},shutter{cur,opts},wb{cur,opts},wbKelvin}]}`
- `POST /cmd` → `{cam:N|"all", action, value}` **или** `{cams:["ip",…], action, value}`
  (список IP — для групповой команды одним запросом). `action`: rec|iso|aperture|shutter|wb|wbkelvin
- `GET /cameras.json` → модели для выпадающего списка + текущие ручные записи
- `POST /cameras/add` `{ip,model,ssh}` · `POST /cameras/remove` `{ip}`
- `GET /groups.json` · `POST /groups/save` (панель владеет схемой, C++ только персистит)
- `POST /restart` · `POST /shutdown`
- `GET /liveview/<n>.jpg` (+ заголовок `X-Cam-Frames`) · `GET /` панель · `GET /<file>` статика

**Выбор LAN-адреса для `server`:** `GetAdaptersAddresses` (линк `iphlpapi`), пропуск выключенных
и loopback; вес = `ipScore` −60 за виртуальный IfType (tunnel 131 / PPP 23 / propVirtual 53)
+25 за настоящий шлюз (не 0.0.0.0). Кандидаты и веса — в лог строками `[net]`.
⚠️ **Не определять адрес «маршрутом в интернет»** (UDP connect к 8.8.8.8): при VPN проба уходит
в туннель — проверено, выбирался `172.18.0.1` (xray_tun) вместо `192.168.0.176` (Ethernet).

## 3. Как работает процесс (C++)

**Без консоли.** `WIN32_EXECUTABLE TRUE` + `/ENTRY:mainCRTStartup` (подсистема Windows GUI,
но точка входа — обычный `main()`). При старте сам открывает панель в браузере
(`openPanelInBrowser`); при само-перезапуске получает `--restarted` и вкладку не открывает.
Весь `consolePrintf` → **`SignalBox.log`** рядом с exe (прошлый запуск → `.log.prev`),
открыт `_wfsopen(..., _SH_DENYNO)` + UTF-8 BOM.
⚠️ `[System.IO.File]::ReadAllText` лог на живой программе НЕ прочитает (просит `FileShare.Read`,
что запрещает нашу запись) — читать `Get-Content` или явным `FileShare.ReadWrite`.

**Значок в трее.** `trayWorker()` в своём потоке: message-only окно (класс `SignalBoxTrayWnd`,
родитель `HWND_MESSAGE`) + `Shell_NotifyIconW`. Меню: «Открыть панель» / «Перезапустить» /
«Выключить» (id 1001/1002/1003). ⚠️ **Проверять значок через `FindWindow*` нельзя** — message-only
окна так не находятся (дважды получал ложное «нет»). Достоверно — строки лога `[tray] …`;
пункты меню тестировать посылкой `WM_COMMAND` с id в hwnd из лога.

**Единственный экземпляр.** Мьютекс `Local\SignalBox_SingleInstance`. Второй запуск не стартует —
открывает панель работающего и выходит. Тонкости: проверка стоит **до `openLogFile()`** (иначе
второй экземпляр ротацией затрёт лог живого); при `--restarted` ждёт освобождения слота до ~15с,
а `relaunchSelf()` перед `CreateProcessW` зовёт `releaseSingleInstance()` — без этого ломалась
кнопка «Перезапустить».

**Сторож завершения.** `startShutdownWatchdog(8)`: через 8с принудительный `TerminateProcess`.
Нужен потому, что `poller.join()`/`discoverer.join()` могут висеть внутри блокирующего SDK
`Connect()` к несвязанной камере — так появлялись **зомби-процессы** (порт освобождён, процесс жив,
следующий запуск показывал панель старого → иллюзия «не выключался»).

**Брандмауэр.** При старте `maybeOfferFirewallRules()` через COM `INetFwPolicy2` ищет входящее
Allow-правило на свой exe. Нет — MessageBox, при согласии `ShellExecuteExW(verb="runas",
"--firewall")` → UAC → элевированный экземпляр добавляет TCP+UDP с `NET_FW_PROFILE2_ALL`.
Отказ → маркер `firewall-skip.txt`. Ветка `--firewall` обрабатывается **до** single-instance-гарда.
Зачем: Windows выдаёт правило только для профиля из разового окна — из-за этого ПК работал в одной
студии и «слеп» в другой (Public vs Private).

**Свойства камер:** статус `GetSelectDeviceProperties` ~1/сек; rec = `SendCommand(MovieRecord,
Down→Up)` идемпотентно; iso маска `& 0x00FFFFFF`, AUTO=`0xFFFFFF`; **кельвины — только
`CrDeviceProperty_Colortemp`=0x0115** (UInt16), НЕ `WhiteBalancePresetColorTemperature`(0x2A5);
aperture/shutter — `FNumber`/`ShutterSpeed` (мануальная оптика → `opts` пуст).

**MIDI (winmm):** все входы; триггер **CC канал 1 (0xB0), контроллер #17**, на нажатие,
дебаунс 80мс → тумблер записи на всех.

**Live view (~7 fps, по запросу):** поток тянет кадры только для камер с открытым превью.
**Рамки требуют `CrDeviceProperty_OSDImageMode=On`** (иначе `sz=0`); HDMI при этом чистый.
`FocusFrameInfo`(0x121) / `FaceFrameInfo`(0x581) / `TrackingFrameInfo`(0x193); захват = `type==2`.

⚠️ **ГРАБЛЯ:** `snprintf("%.4f")` на RU-локали печатает **запятую** → битый JSON.
Числа форматировать локале-независимо (`fx4()`).

## 4. Обнаружение камер — три пути

1. **Автопоиск** `EnumCameraObjects` (SSDP-мультикаст). Параметр `timeInSec` Sony документирует
   как **неподдерживаемый** — увеличить окно нельзя.
2. **Ручные камеры — `cameras.txt`** (`IP МОДЕЛЬ [ssh]`), управляется из панели
   (раздел «Добавить камеру по IP»): `CreateCameraObjectInfoEthernetConnection` без перечисления.
3. **Автозапомненные — `cameras-known.txt`** (ведёт программа сама, `MAC IP МОДЕЛЬ`).
   Каждая найденная автопоиском камера туда записывается; если в следующий раз автопоиск её
   не увидит, подключаемся по сохранённому адресу. Смена IP по DHCP — поиск по MAC в таблице
   соседей (`GetIpNetTable2`), лог «сменила адрес». Строгая ARP-проверка живости, иначе тихо
   пропускаем (не плодим мёртвые сессии).

**Байт-порядок IP для SDK (из доки):** 1-й октет → биты 7..0 … 4-й → 31..24, т.е.
`192.168.0.5 = 0x0500A8C0` — ровно то, что даёт `inet_pton` в `S_un.S_addr`. Не менять на htonl.
**MAC не обязан быть настоящим** — по доке это лишь идентификатор объекта.

### 🔴 Почему камеры не находятся в чужой студии — РЕАЛЬНАЯ ПРИЧИНА (находка коллеги)

На роутере в **2.4 ГГц ширина канала стояла 20/40 МГц** — камера не находилась;
переключили на **20 МГц** — заработало. В студии юзера тоже 20/40, но там всё работает,
потому что помещение маленькое и эфир чистый.

Механизм: в 2.4 ГГц всего 3 непересекающихся канала, HT40 занимает полдиапазона; та же мощность
размазывается на вдвое широкую полосу (−3 дБ SNR), плюс при соседних сетях точка постоянно
переключается 20↔40 по правилам сосуществования. Мультикаст не подтверждается и не
переотправляется → отваливается первым, unicast выживает за счёт ретраев. Отсюда «ping идёт,
а камеры нет».

**Рекомендация (записана в `ЧИТАЙ-МЕНЯ.txt`):** 2.4 ГГц → ширина строго **20 МГц**,
канал вручную 1/6/11. Прочие подозреваемые: фильтрация мультикаста на точке, IGMP snooping
без querier, Wi-Fi в другой подсети/VLAN, репитер.

## 6. Панель `cam-control-panel.html`

Полностью управляется данными: карточка на каждую онлайн-камеру. `LV_BASE` = origin страницы
(или `127.0.0.1:8787` для `file://`) → работает и с телефона.

**Порядок блоков:** шапка → «+ Группа» → группы → камеры без группы → «Доступ к панели» (адрес+QR)
→ «Добавить камеру по IP».

- **Шапка:** название, две **квадратные кнопки-иконки** (`.icobtn`): круговая стрелка = перезагрузка,
  знак питания = выключение; подсказки «Перезагрузка»/«Выключить»; подтверждение — `innerHTML='?'`
  (кнопка квадратная, слово не влезает). Бейдж live/нет связи.
- **Группы (съёмочные залы):** раскладываются **плиткой по ширине** (`#groupsWrap` grid,
  `auto-fit`, колонка ровно **392px** — с `1fr` растягивались в две карточки). Внутри группы
  камеры **строго вертикально**. Всё центрировано (`justify-content:center`).
  - в шапке группы: **треугольник сворачивания**, имя (правится на месте), **индикатор REC**
    (горит, только если пишут ВСЕ камеры группы; пустая группа не считается), «Запись»/«Стоп»,
    счётчик, ✕. Ниже — ряд регуляторов ISO / Диафр. / Выдержка / ББ (±).
  - **свёрнутое состояние — в `localStorage`, НЕ на сервере**: каждый оператор сворачивает чужие
    залы у себя на телефоне, не влияя на док OBS и соседей.
  - перетаскивание карточек между группами (HTML5 DnD) + `<select>` «Группа» в карточке для тача.
  - **групповая запись — ОДИН запрос** `{cams:[…]}`, чтобы старт пришёлся на один проход;
    шаги ISO/диафрагмы/выдержки/ББ считаются **для каждой камеры от её значения** и уходят
    отдельными `/cmd` (не дублируем таблицы значений в C++).
- **Карточка:** модель, батарея, молния питания, остаток карты, STBY/REC; кнопка «Запись» и блок
  ISO — **высотой 31px** (были 64); ниже диафрагма/выдержка/ББ; Live Preview с рамками и поворотом.
- **Мастер-кнопки «Запись·все»/«Стоп·все» УДАЛЕНЫ** (2026-08-06) — их заменили группы.
- **Модель камеры:** таблица `MODEL_NAMES` с **точным** совпадением + фолбэк «как есть, без
  префикса ILME/ILCE/DSC/PXW/HXR». ⚠️ Раньше был поиск подстроки — `ILME-FX30` попадал под
  правило `FX3` и FX30 показывалась как FX3.
- **QR:** библиотека **qrcode-generator 1.4.4** (MIT, `www/qrcode.js`), `qrToSvg()` поверх
  `qrcode(0,'M')`. Клик по QR → крупный оверлей. Всё офлайн.
- **Шрифты локальные** (`fonts.css` + `fonts\`): внешний `<link>` на Google Fonts **блокировал
  отрисовку** — на телефоне с VPN страница висела чёрной до тайм-аута.

## 7. 🔴 Уроки методологии (читать до начала работы)

1. **Свой энкодер нельзя валидировать своим декодером.** С QR я дважды отчитался об успехе на
   сломанном коде: round-trip сходился и RS-синдромы были нулевыми **потому что я считывал ровно
   то, что сам записал, в том же (неверном) порядке**. Нулевые синдромы НЕ доказывают
   правильность раскладки модулей. Нужен независимый декодер или живой сканер.
   Итог: самописный генератор выброшен, взята библиотека — **подтверждено сканом с телефона**.
2. **Не тестировать на живых данных юзера.** Дважды затирал его группы: один раз тестовый код
   переименовал первую группу и подмешал в неё фиктивные камеры, другой раз я сам обнулил список.
   Правильно: снять копию `groups.json` до теста и вернуть после; ещё лучше — проверять
   вычисленными стилями/DOM, не мутируя данные.
3. **Синхронизировать три копии сразу** (см. §1) и напоминать про Ctrl+F5.
4. **Проверять факты инструментами, а не рассуждением.** Гипотеза «профиль брандмауэра» для
   чужой студии звучала стройно, но реальной причиной оказалась ширина канала Wi-Fi.

## 8. Грабли (must-know)

- Выключать только кнопкой на панели или из трея. Убийство процесса → камера отклоняет новое
  подключение (`0x820A CrError_Connect_FailRejected`). Имя ПК для связывания: `WIN-T1I0U6MAIDA`.
- **`Настр. аутент. доступа` (SSH) на камере отключает функцию «Связывание»** — при включённой
  аутентификации наш путь подключения не работает. Проверять первым делом.
- RU-локаль + `snprintf("%f")` → запятая → битый JSON.
- Рамки фокуса требуют `OSDImageMode=On`.
- CAM-нумерация — по порядку обнаружения, между запусками перетасовывается. **Ключ камеры для
  групп — IP, не «CAM N».** В `updateCard` обязательно `if(d.ip) e.ip = d.ip;` — иначе карточка
  сохранит IP прошлой камеры и уедет в чужую группу.
- POST_BUILD `copy_directory` может разово упасть сразу после линковки (антивирус держит свежий
  exe) — просто повторить сборку.
- Кнопки REC боевые: пишут на карты камер.

## 8-бис. Обновление через GitHub Releases (2026-08-06)

Версия приложения — константа `kAppVersion` в `main.cpp` (сейчас **1.0.0**), показывается
в подвале панели. Репозиторий — константа **`kUpdateRepo`** формата `"владелец/репозиторий"`;
**пустая строка = проверка выключена**, и панель честно пишет «обновления не настроены».

**Как работает:** при старте фоновый поток дёргает
`https://api.github.com/repos/<repo>/releases/latest` через **WinHTTP** (встроен в Windows,
линк `winhttp`), берёт `tag_name` и первый ассет `.zip`, сравнивает версии почастно
(`cmpVersion`, чтобы 1.10 > 1.9). Панель показывает плашку «Доступна версия X» и кнопку.

**Установка — без отдельного установщика.** Занятый `.exe` и загруженные DLL Sony перезаписать
нельзя, поэтому: скачиваем архив в `%TEMP%\SignalBox-update\`, распаковываем встроенным
**`tar.exe`**, запускаем распакованную копию с `--apply-update "<целевая папка>" <pid>`.
Она ждёт выхода старого процесса, копирует файлы через **`robocopy`** (успех = код < 8)
и стартует обновлённую программу. Ветка `--apply-update` обрабатывается **до**
single-instance-гарда.

**Настройка автообновления** — `settings.json` рядом с exe (`{"autoUpdate":true}`),
переключатель «авто» в панели. По умолчанию выключено: обновление по кнопке.

**Эндпоинты:** `GET /update.json` (текущая/последняя/доступно/busy/auto/configured/error),
`POST /update/check`, `POST /update/install`, `POST /update/settings {auto}`.
Сеть — всегда в отдельном потоке: HTTP-сервер однопоточный, качать в нём нельзя.

**Репозиторий: `GIDEONSYSTEM/signalbox`** (публичный — на время тестирования; перед продажами
закрыть и переделать раздачу).

**✅ Проверено вживую:** обновление 1.0.0 → 1.0.1 прошло целиком — скачивание, распаковка,
замена ЗАНЯТЫХ файлов, перезапуск. Новый PID, другой хеш exe, версия в панели сменилась.

⚠️ **Тег релиза обязан быть номером версии** (`v1.0.1`, `1.0.1`). Первый релиз был выложен
с тегом `Minor` — `cmpVersion` посчитал его нулевой версией, и обновление молча «не находилось».
Добавлена проверка: нет цифр в теге → панель пишет «тег релиза не похож на версию».

🐞 **Данные установки НЕ класть в архив релиза.** Первый архив содержал `cameras.txt`, и
обновление затёрло бы список ручных камер студии пустым шаблоном. Исключать:
`cameras.txt`, `cameras-known.txt`, `groups.json`, `settings.json`, `firewall-skip.txt` —
программа создаёт их сама. `robocopy /E` не удаляет лишнее в приёмнике, поэтому всё, чего
НЕТ в архиве, обновление переживает.

**Как выпустить версию:** поднять `kAppVersion` → собрать → упаковать архив (без файлов данных)
→ на GitHub: Releases → Create a new release → тег `vX.Y.Z` → приложить архив → Publish.
`gh` CLI на машине нет, `git` есть.

⚠️ **Безопасность:** программа скачивает и запускает код из интернета. Аккаунту GitHub
обязательно 2FA — компрометация аккаунта = подменённое обновление во всех студиях.
Планируется добавить проверку контрольной суммы архива.
